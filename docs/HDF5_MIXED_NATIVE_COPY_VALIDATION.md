# Native HDF5 copy of mixed compound fields

Padded variable-length compound attributes use a packed HDF5 memory datatype for reads, writes and reclamation. The output retains the original file datatype, offsets, shape and values. In the regression fixture, native staging fell from 256 to 12 bytes per element. Existing file-backed staging and scoped HDF5 metadata caches still apply. HDF5 reads and writes the whole attribute value. Packing reduces record padding without capping the separately allocated variable-length payload. See the [HDF5 attribute documentation](https://support.hdfgroup.org/releases/hdf5/2.1.1/documentation/doxygen/_h5_a__u_g.html).

Mixed compound datasets transfer each tile in the original HDF5 datatype. HDF5 reads variable-length data using the 8 MiB allocation budget shared by all fields in a tile. A tile that exceeds the budget splits and retries, with the existing VLEN budget error if a single record exceeds it. Native writes preserve raw legacy object and region reference tokens, including nulls, with the same cross-file semantics as the former HDF5 object copy. The budget covers native read payload allocations. HDF5 caches, write allocations and process RSS are separate.

A fresh-process macOS probe copied 2,048 records with nested references and 64 MiB of UTF-8 data. Additional peak RSS before readback was 113.6 MiB for HDF5 object copy and 37.2 MiB for tiled transfer. Regression tests compare all fields and raw reference tokens with HDF5 object copy, exercise retry with a small byte limit, and verify the packed native staging size and unchanged attribute storage datatype.

A writable copy of public Kang 2018 was augmented with 700 records containing arrays of mixed UTF-8, object references and region references, plus a padded compound attribute. QC retained 24,562 of 24,673 cells. Export matched the selected cell identifiers and all retained expression values. The new metadata matched HDF5 object copy, and both the public input and the augmented input retained their original SHA-256 digests.

The Rust portable-project test passed on both the public file and the augmented copy, including archive save, restore, rejected incorrect relinking, SHA-256 reconnection to the moved source, restart and historical H5AD export. The Python suite ran 77 tests with two opt-in PBMC cases skipped. Frontend build, 21 frontend tests, 23 Rust core tests and the app compile check passed.
